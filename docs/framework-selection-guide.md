# 框架选用指南

> 回答"这个场景该用哪张卡"。前提立场来自批注层：**"哪个框架好"是伪问题**——框架是滤镜不是答案，同一份材料过不同滤镜看到不同东西；**假设检验 > 框架本身**——先确认框架假设成立再选工具。

## 使用原则

1. **先粗后细**：从汇总层（SWOT / PESTEL）进，需要时再下钻到专门工具
2. **一条线走完再跳线**：同一阅读线内的工具粒度衔接，跨线跳会丢上下文
3. **框架是命名器、是对话起点，不是决策终点**：它给你共同词汇，不替你拍板
4. **每个框架都有假设**：假设失效时工具会"用对了但答案错"

## 场景 → 工具映射

| 你面对的场景 | 先用（粗） | 再用（细） |
|---|---|---|
| 不知从哪开始、要启动讨论 | SWOT（配对成 TOWS） | PESTEL 扫外部 |
| 增长往哪走 | 安索夫矩阵 | 三 Horizons 排时间，蓝海找空间 |
| 业务组合怎么管 | BCG 增长矩阵 | GE/McKinsey（多指标）→ Ashridge（凭 CSF）→ ADL 矩阵（生命周期） |
| 这个行业值不值得进 | 五力 | 三战略选姿态 → 价值链找环节 |
| 未来太不确定 | PESTEL | 情景规划（多路径推演） |

## 常见误用提醒（来自批注层）

- **形式化**：把工具当 PPT 摆设填满格子——工具的价值在讨论过程不在产出物
- **跳过假设检验**：假设未成立就选工具，得到"用对了但答案错"
- **多元化当口号**：安索夫"多元化"格内部风险差异巨大，相关与非相关不能合并处理
- **分数可比性陷阱**：凯纳式 1-5 分跨维度打分要警惕——分解的完整性不冒充变量的独立性
- **蓝海当成功学**：只看赢家案例不复核幸存者偏差；蓝海是重构检查表，不是护身符
- **预测执念**：情景规划产出的是"准备"不是"预言"，要单点数字请回去用预测
