# 麦肯锡 7S

> 通过 7 个相互关联的内部要素诊断组织效能的诊断框架。

## 起源与定位

1980 年由 McKinsey 顾问 Tom Peters、Robert Waterman、Anthony Athos、Richard Pascale 四人在 McKinsey 内部工作期间共同提出（最初是 Peters/Waterman 与 Athos/Pascale 平行研究线的合并）。1982 年 Tom Peters 与 Robert Waterman 在《In Search of Excellence》中将其系统化呈现给大众。该框架最初用于分析美国"卓越公司"为何能长期保持优秀，后续被广泛应用于组织诊断与变革管理。

## 核心内容

七个要素分两组：

- **Hard S**（硬件三件）：Strategy 战略 / Structure 结构 / Systems 系统与制度
- **Soft S**（软件四件）：Shared Values 共享价值观 / Skills 技能 / Style 领导风格 / Staff 人员

诊断逻辑：要素之间的"对齐度"决定组织效能。最常见应用是画出 7S 图，标记每个要素的当前状态，找出未对齐组合。

## 适用与不适用

**适用**：

- 并购整合中评估双方组织差异
- 大型变革项目的现状诊断
- 领导力团队的工作坊

**不适用**：

- 20 人以下创业公司——要素尚未稳定
- 单纯战略制定——本框架偏执行与组织

## 局限与争议

- Soft S 缺乏量化标准，依赖顾问经验，容易"什么都能往里塞"
- 与 Galbraith Star Model 高度重叠，独立价值被质疑
- [争议] 一些学者（如 Richard Pascale）认为 Shared Values 应被视为结果而非独立要素

## 与其他方法论的关系

- **演进**：与 Galbraith Star Model（1970s）几乎同期出现，互相影响
- **对比**：Weisbord Six-Box Model 提供了更精简的替代
- **应用层**：常被作为后续变革框架（如 Kotter 8-Step）的诊断前置工具

7S 是这座仓库的第一张卡片——批注它等于给整个项目补了个"出生记录"。

**经验层**：本库搭建时 7S 是任务清单上的第一张卡（Task 3），fact-check 阶段它的提出年份被修正过一次——那次修正教会我对"年份"保持怀疑，后来一路用到假设驱动那张的批注里。所以这张卡对我有双重意义：既是内容上的组织线第一课，也是流程上的起点。使用经验仍是零：职业上没做过任何组织诊断。消费者侧倒有一个模糊观察：有的店标语写着"顾客第一"，员工却被流程按秒表考核——口号与实际系统打架，当时我只觉得"虚伪"，现在知道这叫 Hard S 与 Soft S 未对齐。

**判断层**：组织线三张清单（7S 七件、星模型五件、BCG 三件）里，7S 最全但也最接近卡片批评的"什么都能往里塞"。我的用法是当"补盲清单"——和 PESTEL 同族（对外的补盲），只是方向朝内。清单类框架的入口价值大于出口价值：进门用它扫一遍，出门的结论还得靠别的。

**反思层**：7S 与星模型高度重叠、独立价值被质疑（卡片局限原话）——连续读两张"近似等价"的框架卡，是我第一次直面"框架冗余"。这没有让我否定其中任何一张，反而加固了增长三角批注里的滤片轮换结论：重叠不是缺陷，是同一现实的多个投影——但前提是使用者知道自己每次想用哪个维度。Shared Values 该是结果还是要素的 [争议]，我记下来不选边。

**关联层**：组织线在此开线：`[[galbraith-star-model]]`（同期，设计取向 vs 7S 诊断取向）、`[[bcg-organizational-advantage]]`（BCG 版精简清单）。与 `[[mckinsey-profitability-tree]]` 的连接待批那张时补。它和 PESTEL 一起构成我的"内外两面镜子"。

**应用偏好**：留白。作业：下次走进任何组织（哪怕一家奶茶店），只挑 Strategy/Systems/Style 三件，各用一句话写我看到的现状，再问哪两件之间有明显裂缝——用最小的清单练"对齐"的语感。
