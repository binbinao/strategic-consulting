# Monitor 价值管理

> 把公司战略与股东价值创造显式相连的价值管理框架，通过识别价值驱动因素和关键指标实现战略—执行的闭环。

## 起源与定位

Monitor Group 由 Michael Porter、Mark Fuller 等人于 1983 年创立 [需核实]，1990s 后与 BCG、McKinsey 并称"战略三巨头"之外的重要策略咨询力量。Monitor 于 2013 年被 Deloitte 收购并入"Monitor Deloitte"。VBM 作为概念在 1990s 由多家咨询公司共同推动（Copeland/Koller/Murrin 在 McKinsey 也有相关著述），Monitor 的特定 VBM 实践 [需核实] 强调"财务指标与运营指标在价值驱动树中一一对应" [需核实]。

## 核心内容

三层级联：

- **顶层**：股东价值衡量口径——可选用 Tobin's Q、经济利润（Economic Value Added, EVA）、或 DCF 折现值
- **中层**：价值驱动因素（Value Drivers）——五类经典分解：收入增长 / 营业利润率 / 所得税率 / 资本效率 / 折现率
- **底层**：运营 KPI——把每个价值驱动因素进一步拆解到可被业务一线影响的指标

落地方法：

- 业务线、产品线、客户群逐层拆解价值贡献
- 战略决策（并购、剥离、新业务投资）通过价值影响估算排序
- 管理层薪酬与价值驱动 KPI 挂钩
- 定期回顾"价值创造进度"，把战略变成可监督的过程

## 适用与不适用

**适用**：

- 多元化集团的资本分配讨论——按价值贡献排序业务线
- 上市公司战略年度复盘——量化战略对股东价值的影响
- CEO 继任后的战略校准——把新战略"翻译"为价值指标
- 大型 PE / 控股集团对被投企业的价值管理

**不适用**：

- 早期初创公司（价值驱动因素尚未稳定，强行套用反而误导）
- 非营利组织（驱动力不是股东价值）
- 高度监管或政策驱动的行业（股东价值非首要 KPI）

## 局限与争议

- "股东价值最大化"作为公司根本目标在 2000s 后受到广泛质疑——对员工、社区、环境的隐性成本被忽视 [争议]
- 价值驱动因素的因果链假设过强——实际经济系统反馈复杂，相关不等于因果 [需核实]
- Monitor 1990s 推动 EVA，但 2000s 后学界对 EVA 解释力结论不一 [争议]
- 框架偏静态——对颠覆性创新、技术跳跃带来的"价值重新定义"应对不足
- Monitor Group 2013 年被 Deloitte 收购后，VBM 实践在 Monitor Deloitte 是否仍为核心方法 [需核实]

## 与其他方法论的关系

- **同谱系**：Booz 能力驱动战略——从"能力"端回答价值创造问题，VBM 从"价值"端回答
- **配套**：Bain 净推荐值体系（NPS）等客户指标可作为 VBM 中"客户终身价值"驱动的运营输入
- **互补**：BCG 经验曲线提供 VBM 中"成本端"价值驱动的长期预测逻辑
- **替代**：股东地图（Shareholder Map）、价值创造地图等简化版工具适用于中小型企业

VBM 在 1990s 是 CEO 圈子的"必备工具"——它把"股东价值"这个抽象目标变成可分解的运营抓手，是 90 年代"股东资本主义"最具体的表达。

**经验层**：我用 VBM 做过几次 CEO 战略校准。最有效的是给一家多元化上市公司做"业务组合价值评估"——把 30 多个业务按 VBM 驱动因素拆开，识别"哪些业务在创造价值、哪些在毁损价值"，由此推动业务剥离或资源重配。最糟的是几次"把 VBM 当 KPI 系统"——客户让每个业务单元都按"价值驱动 KPI"汇报，结果是报表极尽复杂但业务动作不变——VBM 沦为"汇报工具"，没有改变决策。

**判断层**：我用 VBM 做"价值导向的组合管理"，不做"股东价值哲学讨论"。理由：VBM 的真正操作价值是"按价值驱动排序业务"——它把"投哪个 / 退哪个"问题量化了。但"VBM 是否比 stakeholder 价值、ESG 价值更合理"——这是哲学讨论，不该用 VBM 解决。我倾向在客户具体场景里用 VBM 做决策，哲学层留给客户自己的伦理立场。

**反思层**：我对 VBM 最大的反思是"因果链假设"——VBM 假设"提高某个驱动因素 → 提升股东价值"。但实际经济里相关性 ≠ 因果——很多 KPI 与股价相关但没有因果。我见过最严重的失败案例：一家 SaaS 客户按 VBM 优化"客户终身价值（CLV）"指标，结果把客户成功团队 KPI 改为"客户续费率"。团队为了让续费率高，把低使用率客户硬留 6 个月，最终用户口碑崩坏、流失集中爆发——优化了 KPI 但毁了实际业务。我的偏好是 VBM 必须配合"反向压力测试"——每个 KPI 优化是否带来反向风险，必须有测试机制。

**关联层**：VBM 与其他工具的搭配——
- 与 `booz-capabilities-driven-strategy` 是"价值端 + 能力端"组合
- 与 `bain-net-promoter-system` 是"财务端 + 客户端"组合（NPS 是 VBM 客户终身价值的运营输入）
- 与 `bcg-experience-curve` 是"诊断当下 + 预测长期"组合
- 与 `kearney-strategic-fitness` 是"VBM 看价值 + Kearney 看运营"的组合

**应用偏好**：我用 VBM 的场景：
- 多元化上市公司的组合管理（资本配置 / 业务剥离 / 收购）
- CEO 继任后的"100 天"战略校准
- 上市公司战略复盘（量化各业务的股东价值贡献）

我不用 VBM 的场景：
- 初创公司（驱动力未稳定）
- 非营利组织（驱动力不是股东价值）
- 客户文化不重视财务（VBM 会被视为"股东至上"，引发员工反感）
