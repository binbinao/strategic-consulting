# 明托金字塔原理

> 把分析结果组织成"自上而下"的金字塔结构（结论先行 → 分论点 → 事实）的思考与沟通框架，是 MECE 原则的应用形态。

## 起源与定位

1987 年由 Barbara Minto 出版 *The Minto Pyramid Principle: Logic in Writing, Thinking* 一书系统化（前期在 McKinsey 工作时内部已发展、离开 McKinsey 后通过 Minto 培训机构推广多年）。该框架建立在 Minto 1960s 在 McKinsey 提出的 MECE 原则之上，是 MECE "拆分"的对应面 "重组"：把 MECE 子问题组织为有说服力的层级结构。Minto 离开 McKinsey 后创办 Minto 培训机构，专职教授金字塔与 MECE。

## 核心内容

金字塔三层结构：

- **顶部**：Governing Thought（核心结论 / 主张）
- **中层**：3-7 个 MECE 子主张，各自支持顶层
- **底层**：每条子主张下的"思想组"——同一逻辑关系（演绎 / 归纳 / 时间序列）

写作规则：

- 同层内关系必须显式：演绎（前提 → 结论）/ 归纳（事实 → 结论）
- 顺序由读者关心度排序，最关心结论放在最上

与 MECE 的关系：MECE 把问题"拆分"为子树，金字塔原理把子树"重组"为有说服力的层级结构。

## 适用与不适用

**适用**：

- 咨询 deck 的 storyline 结构
- 客户备忘录 / 白皮书 / 政策报告
- 复杂分析内部汇报（自上而下宣讲）

**不适用**：

- 创意思维发散阶段
- 探索性对话——先封顶会过早收敛听众
- 现场问答（Q&A 没有固定听众，结论先行有时反而不自然）

## 局限与争议

- 强金字塔隐喻——复杂网状问题被强行线性化
- 听众是"读者型"才有效；对方若边读边跳，效果被破坏
- 实务中"3-7 个子论点"的边界常被打破——多层级金字塔维护成本高
- [争议] "演绎 / 归纳" 二分是否足够，部分学者加"时间序列"
- [争议] 沟通内容强先结论——可能错失读者在底部细节处的洞察

## 与其他方法论的关系

- **基础**：MECE（拆分原则）+ 该框架（重组原则），作者同一人
- **应用层**：所有咨询 deck 都默认采用金字塔结构，被称"咨询界的隐藏标准"
- **替代**：Barbara Minto 后续的"逻辑树 + 金字塔"扩展
- **配套**：与假设驱动 problem solving 几乎总是一起使用（金字塔便于假设表述）

> ⚠️ 示范模板：以下内容为"宗门大法师"风格示范稿，是给 owner 学习"个人批注长什么样"用的样例。owner 必须用自己的真实项目经验替换所有具体场景描述；具体数字、公司名、职位等 owner 没经历的细节应删除或重写。

金字塔原理是 MECE 的"装"侧——配合 MECE 的"拆"侧形成完整的咨询沟通体系。我用金字塔写过十几次客户 deck。

**经验层**：我用金字塔的几次效果两极分化。最有效的几次是给董事会写"投资推荐"——结论先行（"建议投资 / 不建议"），3-4 个分论点，底部数据支撑。这种"自上而下"结构让董事会能在 10 分钟内决定。最糟的几次是给"技术客户"——技术决策需要"先细节后结论"，金字塔结构反而让人不耐烦，因为客户想先看具体技术对比，再听我推荐。

**判断层**：我用金字塔做"异步沟通"（读 deck、备忘录），不"同步对话"（Q&A、对话）。理由：金字塔结构对"读者"有效——读者从顶部开始，决定"是否继续看"。但对"听众"无效——听众在我讲到结论时想打断问细节，金字塔结构强迫他们"听完再问"。我倾向做异步 deck 用金字塔结构，做同步汇报（季度业务回顾、客户现场会议）时改用"主题+开放问题"结构——让听众主导节奏。

**反思层**：我对金字塔最大的反思是"读者假设"——框架假设听众是"理性读者"，会从顶部顺序看下去。但现实客户常是"扫读读者"——他们先看图表、看粗体字、看每段第一句。金字塔结构在这些"扫读者"身上效率极低——他们错过了完整逻辑。我见过最严重的失败案例：一份精心设计的金字塔结构 deck，被客户跳读到第二页的某张表，引发了"为什么这个数字这样"的疑问——但金字塔结构让前面所有逻辑都还没讲到。结果客户误解了 deck，浪费了 4 周咨询时间。

**关联层**：金字塔与其他工具的搭配——
- 与 `mece` 是同作者 Minto 的"拆 + 装"组合（MECE 拆，金字塔装）
- 与 `hypothesis-driven-problem-solving` 是"假设 + 表达"组合（假设驱动给思考路径，金字塔给表达结构）
- 与 `porters-five-forces` 等分析工具是"内容 vs 结构"互补（金字塔是结构，五力是内容）

**应用偏好**：我用金字塔的场景：
- 异步 deck 与备忘录（读者主导节奏）
- 董事会投资推荐（决策时间紧）
- 长报告的执行摘要（TL;DR 段）

我不用金字塔的场景：
- 同步汇报（Q&A 会强迫改变结构）
- 探索性对话（先封顶过早收敛）
- 技术对比（客户要先看细节）
